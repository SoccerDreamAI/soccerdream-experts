## English

### Before you flip to public

- [x] `docs/PLACEHOLDERS.md` — every row resolved (done via `./scripts/personalize.sh SoccerDreamAI soccerdream-experts`, which self-checks)
- [x] `docs/assets/team-run.gif` exists and loads (generated by `scripts/make-hero-gif.py`, 20 KB)
- [ ] `LICENSE` replaced with canonical BUSL-1.1 text, NOTICE.md §2 caveat removed
- [ ] Quick start commands **actually work** — run them in a clean container
- [ ] `make lint` passes
- [ ] No secrets anywhere: `git log -p | grep -iE 'sk-|token|password'` is clean

### Repository settings (this is where the traffic comes from)

- [ ] **About** — one sentence, same as the README subtitle. Not "AI prediction platform".
- [ ] **Topics** — fill all 20 slots. Order matters, first ones rank:
      `multi-agent` `ai-agents` `llm` `prompt-engineering` `agent-orchestration`
      `ensemble` `calibration` `explainable-ai` `python` `typescript`
      `sports-analytics` `research-tool` `open-core` `source-available`
      `disagreement-protocol` `red-teaming` `llm-evaluation` `structured-output`
      `yaml-config` `cli`
- [ ] **Discussions** enabled, with categories: `Announcements`, `Q&A`, `Show your team`, `Ideas`
- [ ] **Private vulnerability reporting** enabled (SECURITY.md points at it)
- [ ] **Social preview image** uploaded (1280×640) — decides the click-through on every share
- [ ] **Issues** enabled, blank issues disabled (config.yml handles it)
- [ ] **Wiki** disabled — one source of documentation, not two

### The first 7 days

- [ ] Cut **v0.1.0** as a real Release with notes. A repo with zero releases reads as abandoned.
- [ ] Open 3 issues yourself, labelled `good first issue`. An empty issue list reads as dead.
- [ ] Post in `Show your team` yourself first — nobody posts in an empty category.
- [ ] Submit to: `awesome-ai-agents`, `awesome-llm`, `awesome-multi-agent` (read each list's
      contributing rules first; blind PRs get closed and burn the one chance you get)
- [ ] One technical post that links here — **the architecture doc's "why averaging is banned"
      section is the hook**. Lead with the argument, not the product.

### What not to do

- ❌ Do not describe the repo as "open source" anywhere. One wrong word and the top comment
  on every thread becomes about that word instead of your work.
- ❌ Do not post to betting or tipping communities. It will be read as a tout service and it
  will get the repo reported.
- ❌ Do not buy stars or use star-exchange groups. GitHub detects it and it is unrecoverable.
- ❌ Do not seed the Discussions with fake users. It is obvious and it poisons the well.

### Message discipline

Every public description of this project should pass this test: *does it promise a result?*
If yes, rewrite it. The framing that works is **"a framework for structured disagreement"** —
which is true, defensible, and interesting to exactly the audience that stars repos.

- [ ] 全库无密钥：`git log -p | grep -iE 'sk-|token|password'` 干净

### 仓库设置（流量就是从这里来的）

- [ ] **About** —— 一句话，与 README 副标题一致。不要写「AI 预测平台」
- [ ] **Topics** —— 20 个槽位填满，顺序有讲究，靠前的权重更高：
      `multi-agent` `ai-agents` `llm` `prompt-engineering` `agent-orchestration`
      `ensemble` `calibration` `explainable-ai` `python` `typescript`
      `sports-analytics` `research-tool` `open-core` `source-available`

      `yaml-config` `cli`
- [ ] **Discussions** 打开，分区：`Announcements`、`Q&A`、`Show your team`、`Ideas`
- [ ] **私有漏洞报告** 打开（SECURITY.md 指向它）
- [ ] **Social preview 图** 上传（1280×640）—— 这个决定了每次分享的点击率
- [ ] **Issues** 打开，空白 Issue 关闭（config.yml 已处理）
- [ ] **Wiki** 关闭 —— 文档只留一个真源，不要两个

### 发布后前 7 天

- [ ] 打 **v0.1.0** 正式 Release 并写发布说明。零 Release 的仓库看起来像弃坑
- [ ] 自己先开 3 个 Issue，打 `good first issue` 标签。空的 Issue 列表看起来像死项目
- [ ] 自己先在 `Show your team` 里发一条 —— 空分区没人愿意先说话
- [ ] 提交到：`awesome-ai-agents`、`awesome-llm`、`awesome-multi-agent`
      （**先读各列表的贡献规则**，盲提交会被关，而每个列表你只有一次机会）
- [ ] 一篇技术文章引流——**架构文档里「为什么禁止取平均」那一节就是钩子**。
      先讲论证，再讲产品

### 不要做的事

- ❌ 任何地方都不要把本仓库描述成「开源」。写错一个词，每个帖子下面的热评都会变成
  讨论这个词，而不是你的工作
- ❌ 不要发到菠菜、推荐类社群。会被当成推单服务，并且会招来举报
- ❌ 不要买 star、不要 star 互换群。GitHub 能识别，且不可恢复
- ❌ 不要用假账号在 Discussions 里自导自演。看得出来，而且会把氛围彻底毁掉

### 对外表达纪律

关于这个项目的每一句公开描述，都用这一条检验：**它在承诺某个结果吗？**
是，就重写。真正有效的定位是「一套结构化的分歧处理框架」——
它真实、站得住，而且对「会给仓库点 star 的那批人」恰好有趣。
